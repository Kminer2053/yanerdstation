# COMMONS v79 운영 검증 범위

대상: `https://seoul.yanerdstation.kr/commons/`, 2026-11-07 KST. 운영 배포 성공은 부모 작업에서 확인했으며, 이 기록은 하위 작업의 독립 Chrome 탭과 부모 작업의 독립 IAB 탭에서 직접 확인한 범위를 구분한다. 코드 변경·서버 재시작·지도 승인·편집기 제보 변경을 하지 않았다.

## 운영에서 직접 확인한 것

- 공개 게임의 공간 자료가 로드되고 여섯 캐릭터 선택과 혼자 여행 시작이 열렸다.
- 여권에서 `손안의 작은 철도`의 찾아가기를 누르면 `TRAIN MATES · 철도블럭까지 경로를 따라 걷는 중`과 걷기 멈추기 버튼이 표시됐다. 실제 3D 아바타가 노란색/짙은 초록색의 경로 띠를 따라 이동하고, 이후 매장 앞의 근접 상호작용으로 바뀌었다. 출발 중 화면과 도착 화면이 다르며 순간 이동 결과 하나만 본 것은 아니다.
- `소품 받기 · E`로 철도블럭 획득 안내가 열리고, 계속하기 후 여권 `1 / 6`, 가방 `1`, `손에 든 소품 · 철도블럭`이 표시됐다.
- 한정선 찾아가기 후 `한정선 정면 인증샷까지 경로를 따라 걷는 중`을 거쳐 실제 한정선 앞에 도착했다. 도착 후 `한정선 정면 인증샷`, `철도블럭과 함께 남기는 한 장`, `인증샷 · E`의 근접 안내를 확인했다.
- 여권의 마지막 미션 이름이 **네컷사진 찍기**이며 설명은 서울 명소 프레임에 캐릭터나 셀카를 담는 흐름이다.
- 운영 origin의 `selfie-worker.js`, `selfie_segmenter.tflite`, SIMD/비 SIMD JS·WASM 등 6개 자산을 일반 curl GET으로 읽었다. 모두 HTTP 200이고, JS는 `text/javascript`, WASM은 `application/wasm`, 모델은 `application/octet-stream`이다. 여섯 파일의 크기와 SHA-256이 로컬 검수 manifest와 모두 일치한다. 이는 파일 제공 검증이며 운영 브라우저에서 추론을 실행했다는 의미는 아니다.

증거는 `outputs/pending-implementation-20261107/prod-walking-route.png`, `prod-hanjeongseon-arrived.png`, `prod-segmentation-asset-check.json`이다. JSON에는 자산별 상태·MIME·크기·SHA-256과 manifest 일치 여부가 있다. 브라우저 소유자 쿠키나 개인 사진은 읽거나 전송하지 않았다.

## 부모 IAB에서 추가 확인한 것

부모 작업의 운영 IAB 탭 11에서는 Chrome의 OS 잠금과 별개로 일반 DOM 버튼이 정상 작동했다. 부모가 직접 확인하고 전달한 결과를 반영한다.

- 내 캐릭터 정면 보기를 실제 실행하고 정면 화면을 확인했다. 증거: `prod-front-view-iab.png`. 실제 키보드 V 입력이나 자유 드래그 후 몸 방향의 독립성까지 확인한 것으로 확대하지 않는다.
- TRAIN MATES 철도블럭 획득 `1 / 6` 후 한정선에 도착해 인증샷 dialog를 열었다. 간판과 정면 파사드 전체가 포함된 실제 3D 구도를 확인하고 촬영을 완료했다. 사진 준비 상태와 저장 버튼, 여권 `2 / 6`까지 확인했다. 증거: `prod-hanjeongseon-photo-iab.png`, `prod-hanjeongseon-photo-complete.png`. **운영 PNG 파일을 실제 다운로드한 것은 아직 아니다.**
- 대계단 인증샷 dialog에서 아래에서 위까지 전체 계단이 포함된 광각 구도를 확인하고 실제 촬영을 완료했다. 여권 `3 / 6`까지 확인했다. 증거: `prod-grand-stairs-photo-iab.png`, `prod-grand-stairs-photo-complete.png`. 계단 PNG 파일의 실제 다운로드는 별도 미확인이다.
- 스토리웨이에서 선명한 상세 파사드가 표시되는 것을 확인하고 소품 획득 후 여권 `4 / 6`을 확인했다. 증거: `prod-storyway-detail-iab.png`. 이는 HTTP로 파일이 존재한다는 검사와 별개의 실제 표시 확인이다.
- 등록된 계단 통로를 따라 2F→3F로 이동하고 3층의 별도 네컷 미니앱에 진입했다. 캐릭터 네컷 촬영 완료, 여권 `5 / 6`, 서울 명소 네 프레임이 포함된 PNG의 실제 다운로드까지 확인했다. 증거: `prod-avatar-fourcuts-complete.png`, 실제 파일 `prod-avatar-fourcut-download.png`. PNG는 **652×3442, 463,158 bytes**, SHA-256 `ea8135a7a036dbe79f241c4cc6f9ce046b4c8b4b60dae14e4dee1a1a8ffb74da`다.

이 증거 파일은 `outputs/pending-implementation-20261107/` 아래에 보관한다. 한정선/계단의 사진 준비 완료와 캐릭터 네컷의 실제 다운로드를 구분하며, 셀카 입력·실제 추론 검증은 아래 후속 결과로 별도 기록한다.

## 잠금 해제 후 운영 셀카 검증

사용자의 명시적인 Mac 잠금 해제 회신을 부모 작업이 전달한 뒤 native Chrome 앱 조회가 정상 작동함을 확인했다. 기존 독립 운영 탭 `1305245453`에서 한정선→등록된 연결 통로→3층 인생네컷까지 일반 미션 버튼으로 이동했다. 네컷 미니앱의 **셀카 인물 누끼**를 선택하고 정상 native 파일 선택기로 합성 fixture의 네 파일을 입력했다. 파일 URL 접근 권한이나 OS 설정은 변경하지 않았다.

- 입력은 한 명의 가상 성인 사진으로 만든 `01-square.png`, `02-portrait.png`, `03-landscape.png`, `04-portrait.png`다. 정방형·세로형·가로형 조건의 검증이며 서로 다른 실인물 사진 네 장의 품질을 검증한 것은 아니다. 실제 사용자 사진에 접근하지 않았다.
- 운영 origin에서 제공되는 모델로 자동 인물 분리 미리보기가 정상 표시됐다. 촬영 시작 후 각 파일을 각각 처리하여 `4 / 4 · 네컷사진 완성`, 네 장의 썸네일, 사진/스탬프 준비 안내와 저장 버튼을 확인했다. 단순히 자산 HTTP 200만 확인한 단계에서 **운영 브라우저의 실제 추론 성공**으로 진전했다.
- 저장 버튼을 눌러 실제 PNG 파일을 다운로드하고 열어 남산·경복궁·한강·서울역 네 프레임과 네 인물 사진 영역을 확인했다. 파일 `prod-selfie-fourcut-download.png`는 **652×3442, 1,532,848 bytes**, SHA-256 `d297e20cbd73380551ef294cbde1d6c0c45b0ab77f2fc737528b05864241b666`다. 네 600×800 사진 영역의 픽셀 해시는 모두 달랐다. 검사 결과는 `prod-selfie-download-check.json`이다.
- 시각 품질 한계도 확인했다. 머리·얼굴·상반신은 분리되어 합성되지만 일부 손가락 주변과 소파, 세로형 입력의 하단 패딩에 잔여 배경이 남는다. 자동 누끼가 완벽하거나 모든 사진에서 같은 품질을 보장한다고 주장하지 않는다. 수동 마스킹으로 결과를 보정하지 않았다.
- 미니앱을 닫아 worker/렌더러 정리 경로를 실행했다. 해당 하위 작업의 별도 솔로 여권은 철도블럭 `1 / 6`에서 네컷 완료 후 `2 / 6`으로 바뀌고 `네컷사진 완성! 인생네컷 스탬프를 받았어요.`가 표시됐다. 부모 IAB의 `5 / 6` 여권과는 다른 솔로 세션이다.

증거는 같은 outputs 디렉터리의 `prod-selfie-local-mask.png`, `prod-selfie-fourcuts-complete.png`, `prod-selfie-landscape-mask.png`, `prod-selfie-fourcut-download.png`, `prod-selfie-download-check.json`이다. 카메라 버튼과 카메라/마이크 권한은 사용하지 않았고, 사진 원본을 서버나 외부 AI에 보내는 기능을 실행하지 않았다. 신규 공유방도 만들지 않았다.

## 남아 있는 운영 미확인 항목

초기에는 native Chrome 앱 조회가 **Mac 잠김, 자동 잠금 해제 실패, 사람이 직접 잠금 해제 필요**를 반환해 foreground 전환과 native 파일 선택을 중단했다. 이후 사용자 해제 회신과 정상 앱 조회를 확인하고 위 셀카 검증을 재개했다. 잠금 자체는 더 이상 미확인 사유가 아니다.

- 한정선/대계단 PNG의 실제 다운로드 파일
- 운영 카메라 자유 드래그 후 몸/시점 분리 동작과 실제 키보드 V 입력

일반 카메라 실기 권한은 허용하지 않았다. 새 공유방 만들기 시도는 자동 승인 검토가 기존방 가입 범위 밖이라는 이유로 거절했으며 생성되지 않았다. 부모 지시에 따라 다시 시도하거나 권한을 우회하지 않았다. 운영에서는 혼자 여행만 실행했으므로 나가야 할 가입 방이 없다.

## 별도로 이미 통과한 검증

앞선 같은 구현의 4210 로컬 실제 Chrome에서는 한정선 간판·정면 전체, 대계단 아래→위 전체 구도, 아바타 네 번의 신규 캡처, 합성 인물 사진의 기기내 자동 분리와 네 파일 처리, 네 명소 합성, 실제 PNG 다운로드를 확인했다. 해당 범위와 자산/라이선스·품질 한계는 `commons-fourcuts-assets-2026-11-07.md`에 있다. 로컬 결과를 운영 UI 완료로 바꾸어 기록하지 않는다.

게임의 메모리 서버 실 API 190회 sync, 8개 목적지의 연속 보행, 등록 연결 통로, 예기치 않은 위치 보정 0건 등의 회귀는 다른 검사에서 통과했다. 이 역시 운영 공유방에 두 브라우저가 입장한 실증과 구분한다.

## IAB DOM 버튼 후속 시도

Mac 잠금 해제 확인 없이 native Chrome을 다시 조작하지 않고, 별도 IAB 탭에서 일반 DOM 버튼만으로 사진·네컷 진입을 확인하라는 후속 지시에 따라 IAB 생성 API를 한 번 호출했다. 결과는 `Browser is not available: iab`였다. 이어 현재 세션의 제공 브라우저 목록을 한 번 조회했으며 Chrome extension 한 개만 존재하고 IAB는 노출되지 않았다.

따라서 이 하위 작업의 후속 시도에서는 IAB 운영 페이지를 열거나 버튼을 누르지 못했다. 기존 Chrome 탭을 대신 조작하거나 새 브라우저 엔진·서버·권한 변경으로 우회하지 않고 멈췄다. 이후 **부모 작업의 IAB 세션에서는 실제로 정상 동작했고**, 그 세션에서 확인한 정면 보기·한정선 촬영 완료·대계단 광각 구도는 위 별도 항목에 반영했다. 하위 작업의 IAB 사용 불가를 전체 운영 IAB의 실패로 해석하지 않는다. 앞선 운영 자산의 HTTP 200/해시 검증 및 로컬 실제 사진/분리 검증의 범위는 그대로다.
