## 확인된 상태

- 사용자가 원하는 연결 대상은 Codex 앱이다. 현재 공개편집기에는 `Dots 연결 관리`, `에비`라는 기존 고정 문구가 남아 있다. 해당 이름은 현재 방문자의 Dots 계정이나 개인 에이전트 정보를 조회해서 표시한 것이 아니다.
- 연결은 MCP와 일회용 코드로 Sites에서 확인한 사용자 식별자를 승인자에게 묶는 구조다. Codex 작업자도 같은 MCP를 사용하는 구현과 검증 기록이 있어 Dots 전용 통신 방식은 아니다. 다만 현재 화면의 첫 연결 안내는 Dots를 기준으로 작성돼 있다.
- `server/dots-auth.js`에는 승인자별 연결 코드 발급·연결 조회·전체 해제가 이미 있다. 연결 코드는 15분, 작업 접근은 7일이며, 초안 작업 범위만 부여한다. 사용자별 계정 식별·첫 연결·재연결·개별 해제의 전체 UX와 접근 경계는 후속 작업에서 확인해야 한다.
- 관리 화면이 제보 상세 안에 접혀 있고 연결 요청문과 대화 상대 이름에 개인 호칭이 고정돼 있다. Codex 앱 열기(요청문 입력)와 MCP 계정 연결, 자동 작업 실행은 구분해 안내해야 한다.

## 일괄 처리할 요구사항

1. Codex 앱을 기준으로 연결 화면·요청문·작업 상태의 용어를 정리한다. 기존 엔진 식별자와 저장 데이터의 호환 여부는 별도 판단한다.
2. 개인 에이전트 이름의 하드코딩을 제거한다. 확인하지 않은 GPT 계정·이메일·에이전트 이름을 알아낸 것처럼 표시하지 않는다.
3. 첫 사용자가 제보 선택 전에도 연결 방법과 권한 범위를 확인할 수 있도록 한다.
4. 각 승인자와 각자의 GPT 계정 연결을 구분하고, 연결 대기·연결됨·만료·해제 상태와 기한을 표시한다. 다른 계정의 제보·파일·작업이 섞이지 않도록 확인한다.
5. 연결 해제, 계정 변경 후 재연결을 제공한다. 개별 연결 해제와 전체 해제의 범위 및 기존 작업 처리 방식을 명확히 한다.
6. 앱에서 요청문을 연 것, 실제 계정 연결, 작업 시작·답변·초안 반환을 각각 구분한다. 미연결·수동 전송·자동 실행 여부를 실제 상태대로 알린다.

이번 점검에서 구현 코드·UI·계정 설정·운영 배포는 변경하지 않았다. 이 문서는 후속 일괄 작업을 위한 보류 기록이다.

## 추가 확인: 로컬 코드와 운영 플러그인의 연결 실패

2026-11-06 오후 11:19·11:21에 새로 만든 코드를 넣어도 즉시 거절된다는 사용자 화면을 확인했다. 일회용 코드 원문은 기록하거나 재사용하지 않았다.

- 오후 11:21:01에 발급한 연결은 `127.0.0.1:4197` 시연 서버의 메모리 DB에 여전히 미연결 상태로 남아 있었다. 연결 접근 기한은 11월 13일 같은 시각이었다.
- 설치된 Toolkit 플러그인은 배포된 Sites 서버를 호출하며 사용자의 로컬 메모리 DB를 조회하지 않는다. 따라서 로컬에서 발급한 코드는 운영 플러그인에서 찾을 수 없다. 새 코드 재발급만으로 이 서버 불일치를 해결할 수 없다.
- 현재 서버는 코드 행을 찾지 못한 경우, 승인자 비활성, 만료, 취소 또는 다른 계정에 연결된 경우를 동일한 오류 문구로 합친다. 오류만으로 코드가 실제 소비되거나 만료됐다고 단정하면 안 된다.
- 후속 일괄 처리에 발급 화면의 로컬/운영 표시, 같은 서버의 MCP로 연결하도록 하는 안내·검사, 실패 원인의 구분을 추가한다. 현재 승인자 설정에서 빠진 이름의 기존 로그인 세션으로 새 코드를 만들 수 있는지도 함께 보완 대상으로 기록한다.

연결 상태 메타데이터만 확인했다. 코드 재발급·사용·연결·해제, 구현 수정과 운영 설정 변경은 하지 않았다.

## 추가 요구: 작업 대화와 결과를 한 화면으로 통합하고 진행 순서대로 배치

2026-11-07 사용자 지시: **이번에도 수정하지 않고 기록만 한다. 기존 보류 사항과 함께 후속 일괄 처리한다.**

현재 사용자는 Toolkit과 Dots/Codex의 대화창을 오가며 요청문을 전달하고 작업 상태·응답을 별도로 확인해야 한다. 제보 사진·설명, 연결 설정, 작업 대화, 저장된 수정안, 분류·처리 기록의 배치도 실제 작업 순서와 맞지 않는다는 피드백이다.

### 한 화면에서 이어지는 작업 흐름

- Toolkit의 해당 제보 화면에서 작업을 지시하고, 연결된 Dots/Codex 작업자의 응답·질문·진행 상황도 같은 작업 지시 채팅창으로 받아 확인할 수 있어야 한다.
- `작업 요청문 확인` 또는 외부 앱 열기만으로 작업이 이어진 것처럼 표시하지 않는다. 외부 대화창을 반복해서 오가거나 요청문·답변을 직접 옮기는 방식을 기본 작업 흐름으로 삼지 않는다.
- 작업자가 제출한 결과는 같은 제보의 **작업 결과 / 수정안 미리보기**에 연결되어야 한다. 채팅에서 제출했다고 한 결과와 실제 저장된 수정안·미리보기의 상태를 함께 확인할 수 있어야 한다.
- 지시, 응답, 진행 상태, 오류, 결과가 어느 제보·작업에 속하는지 일치시킨다. 이 항목은 목표 동작을 기록한 것이며 자동 호출·응답 수신 기능이 이미 구현됐다는 뜻은 아니다.
- 최종 승인과 지도 반영은 기존 승인자 절차를 유지한다.

### 제보 상세의 표시 순서

제보 목록에서 항목을 클릭하면 **제보 사진·설명이 상세 화면의 가장 위**에 와야 한다. 상세 화면은 다음 순서로 배치한다.

1. **제보 사진·설명**
2. **Codex 연결 설정**
3. **작업 지시 채팅창** — 작업자의 응답·질문·진행 상황 포함
4. **작업 결과** — 저장된 수정안과 수정안 미리보기 포함
5. **제보 분류·처리 기록**

연결 설정이 채팅 내부에 섞이거나, 분류·처리 기록이 작업 결과 사이에 끼는 현재 배치를 위 순서에 맞춰 정리한다. 이전의 Dots·에비 고정 명칭과 계정 연결 관리 개선도 기존 보류 목록과 함께 다룬다.

이번에는 이 요구사항만 문서에 추가했다. 구현 코드, 화면 배치, 계정 연결, 제보·작업·수정안 데이터와 운영 배포는 변경하지 않았다.

## 추가 요구: 지도 배치 화면을 캡처해 같은 채팅에서 재작업 요청

2026-11-07 추가 요구이며, 앞선 **기록만 하고 후속 일괄 처리** 지시를 그대로 적용한다.

- 지도·수정안 미리보기에서 시설물의 실제 배치 결과를 확인한 뒤, 문제가 보이는 화면을 이미지로 캡처할 수 있어야 한다.
- 캡처 이미지를 **작업 지시 채팅창에 붙여 넣기(⌘/Ctrl+V)** 할 수 있어야 한다. 이미지를 첨부하고 위치·방향·크기·외관 등 수정할 점을 글로 설명해 Codex에 다시 전달하는 흐름을 제공한다.
- 같은 제보의 작업 맥락에서 캡처 이미지와 수정 지시를 작업자가 함께 확인하고, 재작업 결과는 다시 수정안 미리보기로 돌아와야 한다. 텍스트만 전달되거나 이미지가 다른 작업으로 연결되지 않도록 한다.
- 작업 흐름은 **지도 배치 확인 → 문제 화면 캡처 → 같은 채팅에 이미지 붙여 넣기·수정 지시 → 재작업 → 수정안 미리보기 확인**으로 이어진다. 최종 승인 전에는 운영 지도 반영으로 이어지지 않는다.

이번 추가 기록에서도 구현·화면·운영 데이터·배포는 변경하지 않았다.

## 추가 요구: 제보함 일괄 작업과 선택적 스케줄 실행

2026-11-07 사용자 요청으로 **보류 목록에만 추가**한다. 지금 일괄 작업을 실행하거나 스케줄을 등록하지 않는다.

- Dots 에이전트가 제보함의 처리 대상 작업들을 읽고, 각 제보의 요청·사진·설명에 따라 작업을 일괄 수행할 수 있어야 한다. 사람이 제보마다 외부 대화창에서 개별로 작업 시작을 지시해야 하는 부담을 줄인다.
- 에이전트의 작업 결과는 제보별 수정안·미리보기로 준비한다. 사람은 결과를 검토해 **보완 요청 또는 승인 처리**를 하고, 보완 요청은 해당 제보의 작업 맥락에서 재작업으로 이어져야 한다.
- 처리 흐름은 **제보함 작업 수집 → 요청별 일괄 작업 → 결과·수정안 확인 → 사람의 보완 요청 또는 최종 승인**이다. 일괄 수행이 사람의 최종 승인 없이 운영 지도를 자동 반영한다는 뜻은 아니다.
- 일괄 작업을 수동으로 실행하는 방식과 함께, 사용자가 원할 때 **스케줄링 잡을 설정해 주기적으로 실행하는 방식**도 지원할 수 있도록 한다. 구체적인 실행 주기·처리 대상·연결 방식은 후속 구현 시 정한다.

기존 단일 화면 작업·계정 연결·캡처 피드백 요구와 함께 후속 일괄 처리한다. 이번에는 요구사항 기록만 추가했으며 구현·작업 실행·스케줄 등록·운영 배포는 하지 않았다.
